# 晴空地产：玩法策划 v0.1

开发基线，不代表成品验收。采用 UE 5.7.4；最终微信发布链路尚未验证。

## 模式和人数

每局 2～4 席位，真人与人机共用上限。支持目标为最多 4 真人联机，以及真人与人机混合。当前为本机模式，默认 1 真人 + 1 普通人机；联机、云存档和玩家地图编辑器待实现。

人机没有额外资源或骰点加成，只使用公开信息决定购买。简单保留现金 2500，普通保留 1500，困难保留 max(800, 对手最高租金×2)。人机每 0.8 秒执行一步；三种策略的实际强弱尚未做统计验证。

## 基础规则

当前席位掷一个六面骰 → 沿路径移动 → 跨起点发工资 → 结算落点 → 可购买或跳过 → 结束回合。地块分起点、地产、机会、税费和休息。

无人地产按标价购买，他人地产收租；自有地产暂不升级。机会随机 +500 或 -400；休息格无效果。现金小于零破产，地产回收为无主，现金归零。租金债权人最多收到破产者实际现金。最后一名未破产玩家胜利。

## 联机设计（待实现）

房间状态：等待 → 对局 → 结算 → 关闭。房主选择地图版本、总人数、人机席位和难度，真人准备后开局。服务端同时限制真人数与总席位数不超过 4，满员拒绝加入。开局冻结地图快照，不允许临时编辑改变对局。

操作携带对局 ID、操作 ID、预期状态版本和操作类型。服务端鉴权、检查当前席位和阶段，生成骰点及事件，执行规则并广播结果。重复请求返回同一结果；版本冲突返回最新快照。人机在服务端使用相同规则。

断线设计提案：单次操作限时 30 秒，身份保留 60 秒后人机暂管；重连玩家在下一回合取回控制。服务端保存房间，房主退出不销毁对局。时限需弱网测试后定版。

## 地图定制

当前数据支持 8～128 格，16×16 坐标范围，数组顺序为路径，第一格唯一 Start，首尾闭合、正交相邻且无重复坐标。名称、类型、地价、租金、工资和初始现金可配置。

计划编辑器流程：创建草稿 → 绘制路径 → 配置格子 → 校验 → 试玩 → 保存版本。云端保存作者、地图 ID、版本和内容摘要。修改发布地图产生新版本，不影响正在进行的比赛。自定义经济地图按娱乐模式处理。

## 云端数据

计划保存用户设置、地图草稿与版本、对局配置、玩家资产、回合状态和人机难度。云端按用户身份隔离；在线对局以服务端数据为准，本地存档不得覆盖在线结果。版本检查防止并发覆盖，操作 ID 保证失败重试不会重复扣款。

云服务商和身份认证尚未接入，也没有上传任何用户数据。

## 实施与验收

1. UE 本地原型：编译、规则测试、完整人机对局、中文触控 UI。
2. 地图编辑器与版本化保存：无效地图拒绝保存，重开内容一致。
3. 权威联机：2/3/4 人客户端验证，第五人拒绝；测试重复操作、乱序、断线重连和人机接管。
4. 云端存档：权限隔离、并发冲突与网络中断恢复。
5. 原创资源、数值调优与微信真机发布适配。

微信最小场景导出必须尽早验证。UE 桌面编译和运行不能证明微信兼容。

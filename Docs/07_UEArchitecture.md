# WarlockArena UE 架构和数据设计

本章是开发方案。玩法与数值来自前面的原版规则，类名、模块名、网络和资源组织是为 UE 实现而设定，尚未写入游戏代码或通过 UE 构建验证。

## 技术基线

采用 UE C++ 承载权威战斗、固定步模拟、购买事务、回合流程和数据校验；蓝图负责场景装配、UI、音效、特效与调参入口。普通术士的模型可以更换，但不让蓝图图表成为伤害、扣款或击退公式的第二份实现。

引擎基线采用用户选定的UE 5.9 Preview 2，下载完成后记录精确版本和编译工具链，先验证安装。没有实际依赖时不预先启用大量插件；输入按LocalPlayer使用Enhanced Input，UI保证双人独立焦点，只有真实需求才引入第三方网络或GAS。

## 职责划分

| 组件 | 责任 | 禁止承担 |
|---|---|---|
| GameMode | 房间规则、阶段推进、服务器胜负裁决 | 客户端独自决定输赢 |
| GameState | 可复制的阶段、回合、服务器截止时间、区域状态 | 持有 UI 实例 |
| PlayerState | 金币、积分、构筑、研究次数、存活与队伍 | 信任客户端上传的余额 |
| PlayerController | 本地输入、目标选择、发请求、UI 与观战 | 直接改权威 HP/金币 |
| LocalPlayer与设备路由 | 每个本地席位的设备、输入上下文、视口和UI焦点 | 让第二手柄默认也控制P1 |
| AIController | 权威端感知、移动/施法决策与合法购物请求 | 读取隐藏输入、绕过冷却或免费购买 |
| 术士 Pawn | 可见角色、位置和表现状态 | 默认刚体摩擦替代地图规则 |
| Simulation | 每 0.03 秒推进逻辑，负责运动和碰撞顺序 | 按渲染帧累积伤害 |
| Combat | 命中、反射、伤害事件、击退、吸血、死亡事件 | 商店扣款 |
| Ability | 施法合法性、冷却、技能实体与模式 | 私有复制一套核心伤害公式 |
| Effects | 可叠加实例、结束和驱散、派生属性重算 | 不可追踪的乘除恢复 |
| Shop | 服务器报价、事务、等级/前置/互斥校验 | 执行客户端传来的价格 |
| Arena | 地面查询、刷地/遮罩、缩圈、障碍布局 | 单靠画面材质决定伤害 |
| HUD | HP/K、技能、商店、结算与错误提示 | 维护另一份永久数值状态 |

首版优先一个游戏模块，使用清楚的目录和对象职责即可。没有真实复用需求时不拆大量插件或服务。

## 固定步模拟

模拟只在服务器推进。保存 previous/current 两份逻辑状态，渲染插值。客户端帧率变化不会改变 0.03 秒步长；服务器卡顿后需要有上限的追赶策略，并记录模拟落后，不能静默丢弃伤害 tick 或把巨大 delta 一次送入碰撞。

逻辑坐标使用二维原单位，统一转换到 UE 世界。主动输入速度与外部动量分开，保留原版去除上步行走分量的语义。角色可以使用自定义 Pawn/移动组件，避免 UE 角色移动和自建模拟同时修改位置。

点击移动产生目标点或寻路路径，再由路径跟随产生期望方向。导航只用于寻找绕柱路线，不替代实际碰撞或自动把岩浆设为绝对不可到达区；玩家必须能被击退入岩浆，也应允许按原操作主动走入。若寻路改变原版手感，按移动验证案例调整。

手柄左摇杆直接提供期望移动方向，右摇杆提供瞄准目标，机器人也产生同类输入命令。三种输入源共用移动、施法和伤害规则；不能各维护一套战斗模拟。本地分屏的两名玩家共享同一个权威世界，各有LocalPlayer与视口；AI有PlayerState但不创建LocalPlayer或额外视口。不得把连接、物理手柄、参赛席位和本地玩家索引当作同一个ID。

高速弹道使用扫掠或连续碰撞，比较同一步的最早交点，避免穿过薄柱或把角色后方的目标先命中。同一事件的 tie-break 使用稳定 ID，保证同帧日志可解释。弹道相互交互以明确的规则表驱动，不让 Actor Tick 调用顺序决定结果。

## 数据模型

| 数据 | 必要字段 |
|---|---|
| RuleSet | 原地图哈希、规则版本、修复开关、人数、回合数、购物时间、金币与积分、保护、缩圈 |
| SkillDefinition | 稳定技能 ID、槽、原研究/技能 ID、模式列表、等级上限、购买/升级曲线、前置、来源和确认状态 |
| SkillLevel | 各模式冷却、伤害、弹速、寿命、半径、击退系数、数量、持续时长、特殊参数 |
| ItemDefinition | 商店 ID、背包 ID 各等级、购买与卖出价、最大等级、互斥组、叠加政策、被动与主动效果 |
| MasteryDefinition | 研究 ID、价曲线、最大研究次数、属性修正、组合购买规则 |
| WarlockState | HP/MaxHP、K、逻辑位置/动量、行走分量、队伍、存活、构筑版本、冷却和效果实例 |
| ProjectileState | 所属者、原施法者、可反射归属、技能/模式/等级、位置速度半径寿命、已命中集与连击计数 |
| EffectInstance | InstanceId、来源、目标、开始/结束步、标签、修正项、堆叠组、驱散和死亡清理政策 |
| DamageEvent | 唯一 ID、逻辑步、来源目标、类型、基础/平减/吸收/最终伤害、冲量、归属与排除标志 |
| Contribution | 受害者到贡献者的累计值、来源类型、最后归属、回合重置标记 |
| ArenaState | 地形配置、当前刷地参数/边界、下次缩圈时间、障碍状态、危险查询版本 |

缺失值用显式 Unknown/Inherited 表达，不能序列化成 0 后当作已确认。每个已迁移数值记录 SourceObjectId/Field/Level 或 SourceFunction/Line。确认状态为字段确认、脚本确认、运行确认、待确认之一；机器导出的完整表是证据，不可直接全量转成正式数据。

技能等级与物体层分开。双模式原数据层常相差 10，而玩家技能等级不变。UE 用 ModeId 和 Level 两个字段，不沿用“等级加 10”这类存储技巧。

派生属性从基础值、永久构筑、装备和当前效果重算，表达清楚加法、乘法、覆盖以及优先级。临时技能精通、头盔有效远程等级与实际购买研究次数必须分开，防止临时效果改变商店价格。

## 网络权威和请求

首版采用 Listen Server。物理、伤害、冷却、购买、缩圈和回合结算由服务器权威决定。数据结构保留切换 Dedicated Server 的可能，但不在首版构建专用服务器基础设施。

无网络时采用Standalone本机权威执行相同规则，支持单人加AI及双人分屏。只有在线房间才需要Listen Server。每个参赛者有独立PlayerState和请求序列；不能把服务器上的第二个本地玩家当作没有权限的远端，也不能按网络连接索引为双人共用金币。分屏与AI的完整约定见章节09。

施法请求包含 SkillId、ModeId、目标位置/方向、输入序号和可选客户端时间；服务器检查所有权、阶段、存活、是否学会、控制状态、冷却和目标合法性。客户端不得上传“我命中了谁、造成多少伤害、给多少冲量”。

购买请求包含商品 ID、构筑版本和请求序号。服务器计算价格和验证结果，将最终构筑与余额复制回来。断线重试或重复 UI 点击只处理一次。模式切换同样通过服务器校验，非购买阶段是否可切换遵循原版可达路径，不能利用切换重置冷却。

首版先做权威移动加插值。若延迟明显影响点击响应，再引入客户端预测与服务器校正，预测方案不得成为客户端决定击退结果的理由。远端仅平滑表现，不插值穿过致死边界而误报地面。

可靠请求用于施法、购买和关键阶段，频繁位置采用合适的复制频率；特效不逐帧可靠广播。伤害、死亡与回合结算使用唯一事件 ID 防止 UI 重播造成重复计分。客户端显示服务器截止时间，不各自倒计时后自行开战。

## UI 和交互

- 战斗 HUD 同时显示 HP 与 K，K 明确为“击退值”。显示技能槽、模式、等级、冷却和控制状态，不显示虚构的法力消耗。
- 商店分技能、物品、精通，商品显示当前真实价、升级后变化、前置条件和不能购买原因；原版翻页可优化成清晰列表，但不能丢失第二页条目。
- 出售明确显示目标物品与实际返还额；无法出售的石头给出原因，不增加新的确认弹窗阻碍普通购买。
- 受击反馈表达命中方向与击退积累；保护、反射、沉默、禁锢和吸收分别表达，不能都用同一层蓝光。
- 死亡后显示观战和本回合结果，仍能理解下一回合何时购物。服务器结算先于胜利动画。
- 配置和原版证据 ID 只在开发调试面板显示，不塞入普通玩家流程。
- 全部HUD、准星、镜头、震动和商店焦点按所属玩家绑定，布局按对应分屏视口计算；禁止默认只使用第一个PlayerController。

## 存档与日志

首版只保存本地设置和可选调试记录。战斗金币、当前技能构筑和积分属于本场房间，不作为永久成长带入下一场。外观/令符账户若以后开发，另设服务与需求，不继承原地图的名称匹配权限。

开发日志至少记录规则版本、回合/模拟步、购买前后余额、事件 ID、HP/K 变化、冲量向量和效果增删。支持固定初态和输入序列回放，用来验证核心规则；服务器重放不依赖不受控的全局随机数。随机种子随房间或测试案例记录。

## 数据与资产校验

在进入游戏或打包前校验商品 ID 唯一、技能层完整、价格非负、互斥有效、前置无循环、引用存在、倍率有限、半径非负、冷却合法。待确认字段不得默默填默认并进入首版开放名单。

地图资产移动通过编辑器/UE 自动化完成。二进制资产不通过文本脚本改写。分析脚本产生的资料不需要被 UE 编辑器导入；正式数据资产生成应另有可重复、可核对的迁移步骤。

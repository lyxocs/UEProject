# WarlockArena 机器人与本地双人设计

本章记录用户新增需求：支持机器人对手，同一台电脑上两人分屏，各自使用一个手柄独立操作。这里的 AI 是参战机器人，不是调用大模型实时控制游戏。这些能力纳入首版，伤害、击退、技能和经济数值继续使用地图基准。

## 首版游玩组合

| 组合 | 交付要求 |
|---|---|
| 一个人加机器人 | 无网络、无需第二手柄，可完成战斗、购物、整场结算 |
| 两个本地玩家 | 同一游戏进程、两个手柄、两个独立视口，可彼此对战 |
| 两个本地玩家加机器人 | 首版总席位最多4，可FFA，也可两名真人同队对抗两名机器人 |
| 网络玩家加机器人 | 保留原定2～4席直连房间能力；机器人由房主权威端运行 |

总席位包含真人和机器人，不能按“4名真人再额外加任意机器人”计算。数据模型仍保留12席扩展。双人分屏连接其他电脑的混合网络房间不进入首版验收，架构不得将每个连接写死为一个玩家，以便后续支持。

不要求用户先创建网络房间才能本地双人游玩。单机和本地双人都使用本机权威世界，同一个比赛状态、同一个安全区域和同一套结算；分屏只增加本地视图，不创建两个互不一致的竞技场。

## 本地加入与设备归属

主菜单提供单人、本地双人、网络房间入口。本地双人界面显示两名玩家的加入状态，第二手柄按加入键认领第二席。加入和退出在大厅或购物等安全阶段进行，首版不做战斗中任意替换真人或热加入。

每个本地玩家拥有独立 LocalPlayer、PlayerController、PlayerState、Pawn、相机和HUD。设备与本地席位绑定，不能把所有手柄事件都交给第一个控制器，不能靠全局 PlayerIndex=0 查找正在操作的人。

第一手柄控制P1，第二手柄控制P2。键鼠单人继续保留；混用键鼠与手柄时必须明确归属，键鼠不能无意同时控制两人。设备重连优先恢复到原席位，不按当前枚举顺序自动交换角色。

设备断开时，离线游戏暂停模拟并提示具体席位，允许原手柄或玩家明确选择的设备重新认领。网络游戏不因一台客户端手柄断开而全局暂停；该席位停止产生主动输入，已有外力、危险地面和伤害照常处理。两种策略明确区分，不能借断开设备冻结联网战斗。

首版优先验证Windows上能被引擎识别为两个独立设备的手柄。尚未获知用户具体型号，不承诺所有蓝牙、DirectInput或厂商专有模式即插即用。正式硬件验收记录型号、连接方式、识别结果和映射；至少需要真实双手柄测试，模拟输入测试不能替代硬件验收。

## 手柄操作方案

手感与映射由代理负责迭代，下表是初始方案，属于新开发决策，不是原地图规则。按动作绑定，允许后续换键，不将Xbox字母直接作为技能ID。

| 操作 | 初始映射 |
|---|---|
| 移动 | 左摇杆，平面直接移动 |
| 瞄准 | 右摇杆，个人地面准星 |
| G 火球 | 右扳机RT |
| F 角色技能 | 左扳机LT |
| D 类技能 | X |
| R 类位移 | A |
| T 类技能 | Y |
| E 类技能 | B |
| C 类技能 | 左肩LB |
| Y 类技能 | 右肩RB |
| 菜单与加入 | Start/Menu，根据阶段处理 |
| 商店导航 | 十字键/左摇杆，确认与返回按该玩家UI映射 |

战斗与商店使用独立输入上下文。买东西时A/B用于确认/返回，不同时触发R/E；结束购物后清除按键残留，避免关闭UI瞬间误放技能。菜单导航有独立焦点和重复速率，每位玩家只操作自己的面板。

右摇杆超过死区后更新瞄准方向。释放或拇指离开去按面键时，保留最后有效方向和准星距离，不能突然朝零向量发射。直线弹道取方向；流星、闪现等点选技能使用地面目标，摇杆有效幅度映射到该技能合法选点距离，准星明确预览。具体死区、响应曲线和距离保持策略由代理试玩调整，不能因此改技能真实射程或冷却。

自身技能忽略无意义的准星距离；二段施法沿用该技能动作，不额外占槽。扳机采用明确的按下阈值与复位阈值，不因模拟值轻微波动重复施法。只有明确支持连发的动作才允许按住重复请求。

首版不提供自动命中或追踪锁定来弥补摇杆操作。必要的准星稳定和方向保持属于输入辅助，不能改变弹道碰撞。震动只发送给对应玩家的手柄。

## 分屏与镜头

默认上下分屏，支持设置左右分屏，两个视口均保持相同世界朝向的俯视镜头。人物移动方向与屏幕方向一致，不使用两边不同旋转造成相同摇杆输入含义不同。

每个视口有自己的跟随、缩放、瞄准标记、技能提示、HP/K和观战目标。镜头尽量同时展示角色、附近危险边界和当前瞄准点，必要时显示屏外威胁指示。不能让P1的技能反馈改变P2镜头，也不能让死亡玩家夺走存活者视角。

分屏HUD按各自视口计算安全区、字号、长宽比和鼠标投射，不直接使用全窗口宽高。P1/P2采用稳定颜色、名字或轮廓帮助辨认；不要仅靠准星颜色区分本人。色彩、命中闪光和震动保持可调。

购物阶段每人有独立商店和金币，同时操作。共用同一个服务器购物截止时间；一人开菜单、查看技能或完成购物不会暂停另一人。离线双人比赛的全局暂停通过明确的暂停菜单发起，不能由某个普通UI抢焦点隐式暂停。

分屏会增加渲染负担，优先用清楚、轻量的场景和特效完成首版。目标为可稳定游玩的60 FPS，实际分辨率与画质根据用户硬件实测确定，不作未经测试的性能承诺；渲染降级不改变0.03秒战斗模拟或AI公平性。

## 机器人能力

机器人必须能参与完整比赛：选择目标、移动、预判弹道、躲避、管理位移冷却、逃离岩浆、远离即将缩掉的地面、施法组合、购物升级、死亡与下一轮复活。

首版先提供一个稳定的标准难度，覆盖首版开放技能及装备。后续增加简单与困难，通过反应延迟、瞄准误差、风险偏好、连招决策与购物策略区分，不改变原版HP、伤害、移动速度、技能冷却或经济。

AI只使用规则允许获得的感知信息。不能读取对手尚未提交的输入、未来随机结果、隐身者的隐藏位置或尚未发生的命中；引擎上能访问全局状态不等于设计上允许使用。感知和反应采用受控延迟，不每个物理步完美躲开所有弹道。

决策优先级：

1. 即将死亡或身处岩浆时优先自救，检查真实合法落点和可用位移。
2. 评估缩圈、边缘、障碍和飞弹的短期风险，选择可站立的路线。
3. 在合理距离保持对敌人施压，优先寻找可把目标推向岩浆的角度。
4. 按命中机会和风险选择技能，保留逃生资源，不盲目轮流释放所有技能。
5. 非战斗阶段使用合法商店请求完成构筑，确保不会等到战斗后仍停在购物状态。

采用可调的效用评分或简单状态机起步，不引入外部LLM推理、训练平台或每次决策的云端成本。全局AI决策可低频更新，移动和飞弹仍由固定步模拟推进；决策频率、反应时间和误差记录为开发参数，不冒充地图数值。

## AI与人类共用规则

AIController输出与真人等价的Move/Aim/Cast/Shop命令，交给同一套权威校验。它不能绕过冷却、控制、同槽互斥、射程、金币、前置或背包限制。购物使用真实余额和价格，失败行为与真人一致，不直接修改研究等级。

机器人有独立PlayerState、积分、贡献、装备和随机种子，死亡照常归属和计分。比赛逻辑按参赛者统计，不按LocalPlayer数量统计；机器人也计入开战人数、缩圈计时与队伍胜负。

购物策略先用数套明确的构筑计划，按当前开放名单、余额和前置逐步购买；预算不足可以存钱。新技能加价、石头、精通套餐、物品互斥全部经过同一个商店事务，不为了让机器人“会玩”免费补齐技能。

机器人只在权威端运行。独立本地游戏由本机运行；网络房间由房主运行，客户端只显示复制结果。AI控制器不得占用本地手柄、创建额外LocalPlayer或分走真人视口。

## 房间配置

大厅至少保存：比赛总席位、人类本地席位、网络席位、机器人席位、队伍分配、AI难度、每席角色和设备归属。提供1v1、FFA、双人合作对机器人这些明确预设；队伍模式改变胜负归属，不改变地图的技能价格和回合补给。

机器人在大厅添加或移除，开战后不自动补人。首版真人离开不静默切成机器人；若以后增加接管，必须另外定义构筑、积分、来源归属与重连政策。

## 验收案例

| 编号 | 情况 | 必须结果 |
|---|---|---|
| LOCAL01 | 两手柄依次加入 | 创建两个独立本地玩家，各自只控制自己的术士 |
| LOCAL02 | P1持续移动，P2瞄准施法 | 输入同时生效，没有焦点或映射串线 |
| LOCAL03 | 双人同时开商店买不同商品 | 各自焦点、金币、构筑和错误提示独立 |
| LOCAL04 | 上下/左右布局与窗口比例变化 | HUD、准星、射线选点及技能预览正确，无跨视口偏移 |
| LOCAL05 | P1死亡、P2存活 | 仅P1切观战，P2继续正常操作和镜头 |
| LOCAL06 | 离线P2手柄断开后重连 | 暂停并明确提示；绑定恢复，不交换P1/P2、不重置比赛 |
| LOCAL07 | 扳机半按抖动、从商店退回战斗 | 不重复误放技能，不触发残留确认键 |
| AI01 | 一名真人对三名机器人 | 无网络也能从购买阶段玩到整场结算 |
| AI02 | AI在岩浆或危险边缘 | 尝试合法自救，不能瞬移作弊或冻结地面伤害 |
| AI03 | 机器人资金不足或冷却中 | 请求失败，不免费获得技能或越过冷却 |
| AI04 | 隐身、延迟与瞄准误差 | 机器人遵守感知与反应限制，不读取隐藏状态 |
| AI05 | 机器人重复购买、死亡、换回合 | 金币、技能、积分和临时效果按照同一套规则处理 |
| MIX01 | 双人同队对两名AI | 队伍胜负正确，无友方贡献重复计分 |
| MIX02 | 双人FFA加两名AI | 四席都计入缩圈与积分；AI不生成视口 |
| PERF01 | 打包版双分屏加AI | 实测帧时间与模拟落后；不能只在PIE或单视口验收 |

## UE依据与待验证项

# WarlockArena 次世代画面和光影目标

用户要求UE版本具备次世代画质，包括现代光影。原地图约束玩法和核心数值，不约束模型、贴图、动画、光照、特效或UI的画质。正式首版需要有统一、完成度较高的可玩竞技场；灰盒仅用于技术验证，不能把占位画面作为最终视觉交付。

## 美术方向

初始方向为高品质魔幻竞技场：有真实材质与空间感的黑曜石、风化石材、金属和流动岩浆，配合有辨识度的术士轮廓、魔法符文和元素特效。构图围绕俯视战斗组织，远景和装饰烘托竞技场，不占用主要操作区域。此方向是代理据现有玩法提出的初始美术方案，后续可以按用户参考调整。

“次世代”通过完整画面的材质、光影、角色动画和效果层次体现，不以引擎开关数量、贴图分辨率或全屏亮光作为唯一标准。画面目标从一张小而精的竞技场样板开始，不在核心玩法尚未验证时购买大量互不匹配的素材。

## 视觉组成

| 部分 | 目标 |
|---|---|
| 竞技场 | 轮廓有厚度、边缘破损与合理比例，石材/金属接触可信；碰撞和视觉边界一致 |
| 岩浆 | 有流速层次、表面冷壳与裂纹、热光变化、局部飞溅和适度热扰动；危险边界始终可辨 |
| 光影 | 明确的环境主光、岩浆暖色反光、角色轮廓光与可信接触阴影，保留暗部细节 |
| 角色 | 高质量可替换角色、法袍/护甲材质、自然移动施法受击死亡衔接，在俯视和分屏尺度仍能识别动作 |
| 法术 | 每类技能具有形状、运动、颜色与音效上的区别，含蓄力、弹道、命中、结束等阶段 |
| 命中反馈 | 短促的亮度、冲击波、火星和碎屑，明确击退方向，不遮住随后飞来的技能 |
| UI | 一致字体、图标、颜色和动效；与现代场景风格协调，分屏下保持清晰可读 |
| 背景 | 火山深渊、远处建筑或魔法结构提供纵深，主战区与背景有明确视觉分离 |

## 渲染方案

优先评估Windows桌面Deferred/DX12路线，按UE 5.9 Preview 2实际支持与硬件能力确认。以下技术是候选实现路径，尚未在本项目启用或完成性能验证。

| 能力 | 用途 | 实施约束 |
|---|---|---|
| Lumen全局光照与反射 | 环境间接光、岩浆与场景的光色联系、材质空间感 | 先测试单视口和双分屏；软件/硬件光追按兼容性与实测选择，不默认要求最高硬件光追 |
| Nanite | 支撑适合的高细节岩石、石柱、竞技场几何 | 按具体资产支持情况使用；不替代碰撞简化、材质优化或内存预算 |
| Virtual Shadow Maps | 高质量动态阴影与细节接触 | 评估动态光源数、阴影更新和分屏成本；不让每颗火球都成为有阴影的点光源 |
| Niagara | 魔法弹道、命中、岩浆环境和技能交互的视觉效果 | 粒子用于表现，逻辑弹道和命中仍由权威模拟计算 |
| 物理基础材质 | 石材、金属、布料、岩浆冷壳和潮湿表面 | 控制粗糙度层次和色彩，不用统一高反光假装材质细节 |
| 时域重建与画质伸缩 | 在目标显示分辨率下平衡清晰度与帧时间；当前高档TAAU、精细档TSR | 在运动、细弹道、半透明与分屏中检查拖影、闪烁和过度锐化 |
| 体积雾和后期 | 环境纵深、色彩和有限的光束氛围 | 不能遮蔽脚下地形、危险边界和瞄准点；曝光不随爆炸反复抽动 |

Lumen与Forward Shading不兼容，因此不能无分析地把低成本Forward配置与Lumen目标同时写为默认。若双视口表现或硬件不支持目标路线，应明确建立替代画质配置并验证，而不是勾选后假定有效。

小而亮的自发光物体不作为所有动态照明的唯一来源。岩浆主环境光与飞弹近场短时补光分别设计，避免噪点、闪烁与过多动态灯。需要照亮角色的关键法术可使用有限数量、有限距离和不投影的局部光，数量预算由实测确定。

Path Tracer可用于离线参考或展示截图，不作为实时对战与分屏的必需渲染路线。不能用离线高质量截图证明实时游戏达到相同画质或帧率。

## 光影和特效可读性

安全地面、岩浆和角色保持不同的明度与色相层次。地面上的法术预告与装饰符文必须可区分；实际受击范围与危险查询不由材质动画临时决定。

火球、闪电、护盾和锁链分别采用稳定的形状和运动特征，除颜色外也能分辨。爆炸的高亮核心短暂出现，后续烟尘不能长时间遮挡视野。Bloom、景深、运动模糊、热扰动和镜头震动按玩法单独约束，正式战斗不为了电影感持续模糊准星或人物。

敌我信息不依赖高画质独占效果；低画质也必须看见相同的技能预警、弹道、命中边界和隐身规则。体积雾、阴影和粒子降级不能让某一档画质更容易识别本应隐藏的目标。

## 双人分屏与画质档位

双人分屏是必需功能，高画质不能只在单视口下验收。两视口的场景与效果成本以实测为准，不能简单假设总像素不变就没有额外开销。

初步设置质量、高帧率和截图展示三类配置：

- 质量配置：保留主要动态光影、精细材质和代表性法术效果；单人和双人分别测量可用分辨率与帧率。
- 高帧率配置：降低非关键阴影、反射、体积雾和装饰粒子成本，维持一致风格和关键玩法提示。
- 截图展示配置：用于静态或非竞争展示，不作为实战默认和性能验收依据。

实时玩法目标保持60 FPS；在确认GPU、显存、显示分辨率和双视口实测前，不承诺原生4K、全光追或所有配置都稳定60。硬件检查属于开发前测量，届时由代理读取环境并提出具体画质预算，不要求用户预先购买升级硬件。

多人服务器规则、AI公平性、技能数值和0.03秒模拟不随画质档位改变。一个本地玩家切换画质涉及共享渲染设置时，由统一设置界面处理，不能让两人分别写互相冲突的全局配置。

## 资源选择

先确定样板画面的材质、角色尺度、光色和代表性技能，再选择能统一风格的资产。优先比较岩浆材质、适配俯视的魔法特效、角色动画与竞技场模块；大面积高写实环境包不是默认采购项。

选包前检查UE5.9 Preview 2实际可用性、是否依赖第三方二进制插件、Lumen/Nanite相关限制、材质复杂度、可调性和使用授权。没有明确需要时不购买，不自动安装付费内容。导入后先在样板关卡检查单人和双分屏，而不是一次性迁入全部资产。

替换美术不改变原单位到UE单位的比例、角色碰撞半径、柱子阻挡、弹速、技能范围和危险地面。需要缩放模型时只改变表现层，回归验证实际命中。

## 视觉样板与验收

核心运动与火球命中成立后，制作一段正式品质竞技场：角色、岩浆、地面、柱子、主环境光，以及火球、闪电和护盾的代表效果。样板必须能实时操控，且支持双分屏查看。样板确认后再将风格扩展到其余技能与完整场景。

| 编号 | 场景 | 验收要求 |
|---|---|---|
| VIS01 | 单人实战相机 | 材质、照明和模型明显超过占位画面，角色与危险边界清晰 |
| VIS02 | 双人上下及左右分屏 | 两视口光照、阴影和反射正常；HUD和细弹道在各自视口可读 |
| VIS03 | 多技能同时命中 | 不产生持续曝光抽动或大面积白屏，能继续判断角色、准星与危险方向 |
| VIS04 | 缩圈与掉入岩浆 | 危险变化在视觉与逻辑上对齐，不出现视觉安全但实际扣血的边界 |
| VIS05 | 相机移动与细弹道 | 检查TSR拖影、粒子抖动和阴影闪烁，不能只验收静态截图 |
| VIS06 | 长时间双分屏加AI | 记录GPU/CPU帧时间、显存和卡顿；区分渲染与模拟瓶颈 |
| VIS07 | 质量切到高帧率 | 风格仍统一，关键战斗信息与命中规则一致 |
| VIS08 | Windows打包版 | 实际资源、着色器与效果可用，不能只在编辑器预览里成立 |

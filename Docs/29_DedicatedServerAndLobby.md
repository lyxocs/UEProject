# Dedicated Server 与联机大厅

## 分支与范围

从单机 v0.10.0（6f50807）创建 `game/warlock-arena-ds`。原 `game/warlock-arena` 保留。联机沿用同一套原图经济、固定步战斗、前摇取消、击退、岩浆、AI和表现代码，服务器拥有最终裁决权。

本版是直连一个专用服务器房间的大厅：2～8总席位、AI补位、至少两位真人，全员准备后进入40秒回合商店。商店再按原规则准备、战斗、结算和下一回合。没有新增账号、自动匹配或多房间调度服务。联机每个客户端一个玩家；离线仍保留本机双人及原设备路由。

游戏内 F11 或左上角“联机大厅”输入服务器地址与玩家名称；地址/名称仅保存在本机生成设置。默认服务地址 `21.6.1.43:7777`，UDP；SSH端口36000用于部署，不是游戏端口。断线/连接失败后返回本机并显示可重试信息。

大厅房主可改总席位、AI五档和自由竞技/玩家合作；所有规则改动都会清除准备状态。手柄A/Enter准备，房主十字键改席位、RB改难度、Y改模式。AI默认准备。房主退出时权限转给剩余玩家；无真人时回到大厅。战斗期间拒绝新加入；商店/大厅可重连，这不是保留账号和金币的掉线续接。

联机 ESC 只打开当前客户端设置并停止其移动/施法，不暂停服务器。画质、音乐、音效、改键仍在本机调整；人数/AI在大厅由房主设置。终局房主可通过“再来一场”返回大厅。断线补位AI不以满血角色中途插入战斗，下一回合正常参战。

## 网络实现

- `WarlockArenaServer.Target.cs` 是真正的 `TargetType.Server`。Launcher版引擎构建Server目标实际报告不支持；普通Game程序的`-server`也未进入DS模式，不能替代服务器交付。
- 使用服务器固定0.03秒模拟，客户端发送拥有者RPC，不发送伤害、命中者、金币或结果。购买仍由服务器校验原图价格/前置/阶段。
- Pawn为自定义运动，增加所有客户端（包括AutonomousProxy）的权威位置/朝向复制；显示根节点短距离插值，闪现/大位移直接就位。没有宣称实现客户端移动预测或高延迟回滚。
- 玩家、AI、准备、等级、经济、HP/K、弹道、法术事件、竞技场状态复制。补齐锁链持续状态与权威链终点更新；服务器不播放音乐、不刷新角色骨骼表现。
- AI使用独立负数PlayerId，真人使用服务器分配ID；玩家控制权、设备索引、Team与身份色相互独立。
- 项目协议号 `0x574C1001`，两端同一份代码与同一UE 5.9 Preview 2（源标签`5.9.0-preview-2`，源码提交`2f66b3f91297f7ad9261f18a70c836fa5472d645`）。源码引擎与Launcher CL不同，使用项目网络版本绑定；没有全局忽略兼容性。未来修改网络协议时递增此号并发布匹配客户端。
- 当前网络预算：服务器33Hz，单客户端上限100000字节/秒，总动态预算800000。需要实际更多客户端/延迟测试后再调，不能从本机双进程推断公网表现。

## 构建与部署

用户已明确授权将引擎源码、游戏Source/Config/uproject、Cook资源、服务端程序与脚本上传到 `/data/home/johnyxliu/srv/warlord` 并启动测试。引擎源码不推送到游戏Git仓库，也不打入玩家包。SSH密钥和账户令牌不入库、不进入部署资源。

服务器为TencentOS 3.2 x86_64。原系统glibc无法加载这版UBT依赖的Blake3 .NET原生库；构建使用 `Dockerfile.build` 的Ubuntu24.04容器与UE官方v26 clang20.1.8 RockyLinux8工具链，不升级宿主glibc。引擎和项目只作为卷挂载，未打进镜像。容器限制CPU/内存，游戏运行资源独立放在`runtime`。

1. `Scripts/Linux/prepare_engine.sh <源归档> <引擎目录>` 准备官方依赖与原生工具链；`build_server.sh`通过官方BuildUBT发布构建工具。旧宿主环境用`build_in_container.sh`执行编译。
2. Windows官方跨编译工具链可解压到工作区工具目录，给Cook进程传`LINUX_MULTIARCH_ROOT`，不强制改系统环境变量。
3. LinuxServer资源使用UnrealEditor-Cmd Cook，`-targetplatform=LinuxServer -SkipZenStore -unversioned -nullrhi`，生成可独立部署的Cook文件。不得直接上传`ue.projectstore`或Zen认证配置。
4. `make_server_resources.py --engine <引擎目录>` 仅收集Cook资产、必要引擎运行数据、项目配置与AI策略；`stage_server.py`按Linux目标receipt拷贝真正的服务端及运行依赖、所编译插件的描述/配置。
5. `server_ctl.sh start|stop|status` 管理自有进程，PID对应可执行文件路径不符时不发送信号。`WARLOCK_PORT`默认7777，`WARLOCK_SEATS`默认4。日志在`logs/`，本机服务器生成设置在runtime的Saved，不入版本库。

Windows玩家包继续通过`Scripts/Package.ps1`构建；玩家PC不需要UE或VS，使用与服务器匹配的联机版本。

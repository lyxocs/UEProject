# 施法、双人输入与火焰表现

本章保留旧版迭代记录。当前八技能前摇与抬杖/取消动作以[第20章](20_AllSkillAnticipation.md)为准，不再使用下方较短的旧预设。

2026-11-26 用户试玩反馈后的修正；覆盖之前“立即释放”和“右摇杆瞄准”的样机约定。

## 施法阶段

技能先进入待释放状态，结束前摇后才生成法术、扣除自伤、开始冷却。前摇中不能叠加第二个技能；S、鼠标中键或手柄R3可以取消，右键移动也会取消。取消不扣生命、不开始冷却；效果已经释放后不能撤回。死亡、结束回合和重开会清除待释放状态。前摇期间主动行走停止，外力仍然生效。

| 技能 | 前摇秒数 | 动作 |
|---|---:|---|
| 火球 | 0.18 | 挥杖攻击 |
| 天罚 | 0.70 | 举杖后下砸 |
| 闪电 | 0.25 | 举杖施法 |
| 闪现 | 0.09 | 快速施法 |
| 火焰喷射 | 0.30 | 挥杖 |
| 流星 | 0.45 | 较慢的举杖下砸 |
| 反射盾 | 0.16 | 举杖施法 |
| 锁链 | 0.22 | 向前挥杖 |

天罚0.7秒直接依据原地图 `S001` 的 `acas[1]`、`Ncl1[1]`（原始float32约0.699999988）；`EVENT_PLAYER_UNIT_SPELL_EFFECT` 驱动效果，原样机漏掉了施法时间。0.03秒固定步在0.69秒仍未释放，下一步0.72秒结算。其他前摇是用户授权的UE手感预设，不冒充原地图已确认的缺省基础数据；伤害、购买和基础冷却保持原值。

使用现有 Attack、Attack Slam、Spell 三段骨骼动作，按技能分配和调整播放速度，并非已经制作八段全新动画。抬手与真实释放阶段绑定，HUD显示施法名称、剩余时间与进度。

## 弹道与AI

用户要求慢一些的默认预设：飞行速度乘0.78，寿命除0.78以保留射程；火球1000→780单位/秒。固定步寿命截断导致实际距离在一个步长误差内。闪电仍是射线、天罚仍为范围结算，不将它们伪装成慢速飞弹。

`UWarlockTuning` 在 `Config/DefaultGame.ini` 配置，`Windups` 数组顺序为上表，`ProjectileSpeedScale=1` 可恢复基准弹速。慢速预设属于明确的用户体验调整，不改写原地图数值证据。

AI观察窗口为0.45–0.75秒，受0.22秒决策采样量化；实际决策可能更晚。发现新目标、目标闪现或新近身飞弹后重新等待，等待中不会读取新位置立即反制。每次最多选择一个技能，使用相同前摇，并有至少0.5秒技能决策间隔。无需降低机器人伤害制造难度差。

## 本地操作

- F8：P1只用键盘，方向键移动并决定朝向，G/F/D/R/T/E/C/Y施法，Tab/Enter购物，S取消。P2只用鼠标，指向瞄准，右键移动，滚轮选技能，左键释放，中键取消；可以点击技能栏、商店按钮与确认按钮，侧键1打开商店、侧键2天罚。
- F2：两只手柄分别控制P1/P2，左摇杆移动并决定朝向，松手保持方向，原技能键释放。右摇杆不再瞄准，R3停止/取消；View购物、A确认、B返回。
- F3：P1键鼠，第一只手柄控制P2。
- Esc / Menu：暂停或继续。暂停冻结整场游戏、AI、飞弹、技能前摇和阶段计时，屏幕显示可点击的继续按钮。暂停时不能通过鼠标继续攻击。

准备阶段界面提供模式提示与可点击入口。三个模式可互相切换，不添加第五席位。通过独立GameViewportClient在输入进入PlayerController之前将鼠标路由给P2；P1不读取鼠标瞄准，P2不轮询键盘移动。不是只把一套键鼠映射复制给两个玩家。

```powershell
Scripts/Run.ps1 -Packaged -Mode KeyboardMouse
Scripts/Run.ps1 -Packaged -Mode TwoPads
```

## 火球表现

火球与火焰喷射使用原创程序火焰材质、加色精灵火焰拖尾和飞散火星，核心持续旋转翻滚。每颗火球最多20个视觉粒子，喷射弹最多10个；纯视觉在客户端更新，碰撞半径和方向不随视觉旋转变化。原型使用原生材质精灵粒子池，未冒充完整Niagara效果库；没有采购外部资产。材质创建脚本为 `Scripts/create_fire_material.py`，只创建缺失资产，不覆盖后续编辑。

## 验证方法

`Scripts/verify_casting_controls.py` 在默认预设下验证前摇、取消、单次释放、死亡清理、慢速弹道与射程、AI闪现反应、真实视口键鼠路由、手柄角色隔离与禁用右摇杆、暂停/恢复。报告为 `Saved/Validation/casting-controls.json`。

`verify_full_flow.py` 将前摇临时设为0、弹速设为1来隔离原有伤害/经济/11回合测试，使用finally恢复默认预设。它不能替代默认施法测试。真实双手柄及重连仍需连接设备实测；软件注入通过不等于真实硬件验收。

本轮默认预设33项、既有输入20项、角色9项、原数值/回合88项、规则自动化3项均通过。Editor与Game目标完整编译通过，Windows开发包BuildCookRun通过。键鼠分开双人和暂停画面为 `Saved/Validation/visual-keyboardmousefight.png`、`visual-pause.png`。另外修正P2本地HUD命中框的坐标换算，防止点击技能选择时同时释放；这一修正随后重新编译，并复用刚刚通过的资源烘焙重新归档。

最终开发包通过原生 `ke WarlockPawn Cast 0` 定向释放并截图，`Saved/Validation/visual-fireball.png` 实际显示四枚火球向场中飞行、橙色精灵拖尾与细小火星，未见材质回退或致命错误。它是受控视觉检查，不当作真实玩家交战；旋转由视觉网格逐帧更新，不改变扫掠碰撞。程序火焰仍是第一轮表现，尚非最终Niagara美术质量。当前未重新宣称上一轮AI加速整场测试代表这套新AI预设的自然整场结果。

`Scripts/Package.ps1 -ReuseCook` 仅适合已经成功烘焙、之后只改C++的快速归档；资产或配置发生变化时使用普通完整打包。

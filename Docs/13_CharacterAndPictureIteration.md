# 术士角色与画面迭代

本轮对应用户要求：接近原图术士，具备行走与施法动作，提供多套美观外观，并改善实际试玩画质。当前属于可运行的美术迭代，尚未达到正式次世代角色品质。

## 角色依据与可复现流程

原地图普通术士 h000/k000 实际引用 `WarlockModel.mdl`，模型缩放 0.92；MPQ 内对应二进制 `WarlockModel.mdx`。只读提取位于 `Analysis/Warlock1.00b CN/Models/`，模型 SHA256 为 `df228081208840028f407f8be040fd7f3b1c12e3ca40651f088d54c1cbf7cc1d`。

`Scripts/convert_warlock_model.py` 转换原始网格、51节点骨骼、蒙皮和关键帧，产物为 `AssetsSource/Warlock/Warlock.glb`，转换报告为同目录 `conversion.json`。输出待机、行走、攻击、施法、死亡和重击六段动画；粒子、材质动画和动态网格可见性不在本次转换范围内。UE 资产通过 `Scripts/import_warlock_character.py` 的编辑器导入接口生成，保留已存在资产，不直接改写 uasset。

原模型引用的基础游戏贴图不包含在用户地图中。本轮使用项目自建布料、金属、皮肤和发光材质替代，未安装 Warcraft III，也未声称恢复原版完整贴图。原图资源用于当前项目内部对照；没有将地图资源视为已获得公开发行的商业授权。

| 外观 | 配色与头饰 | 战斗影响 |
|---|---|---|
| 赤曜术士 | 暗红布料、旧铜、克制的火色点缀、三峰冠 | 无 |
| 霜月术士 | 灰蓝布料、哑银、灰蓝发光点缀、月角冠 | 无 |
| 幽林术士 | 墨绿布料、暗铜、低饱和绿点缀、分叉角冠 | 无 |

准备阶段按 H / Xbox 左摇杆按下切换；机器人分配不同外观。颜色和头饰由服务器外观索引决定，复制给客户端。身份辨识仍由独立队伍标记承担，外观不改变半径、属性、金币与技能。

用户最新要求为配色略偏写实：整体降低饱和度，区分布料与粗糙旧金属，不以大片自发光替代材质。配色存于 `/Game/WarlockArena/Characters/DA_WarlockAppearances` 数据资产，包含三个外观的布料、金属、点缀色与共用肤色；后续在编辑器调整，不必改C++。脚下身份标记采用细符文环，中央透明。

后续“人物、场地、UI再精细一些”的迭代：`Scripts/refine_character_mesh.py` 对13个布料/兜帽分区进行两级带蒙皮细分，局部三角面由413增加到6608，平滑法线并限制原顶点移动，保留原始UV、51骨骼与六段动画。派生GLB位于 `AssetsSource/Warlock/Refined/`，UE资产在 `Characters/RefinedWarlock/`；源模型与初始转换保留用于对照。这是曲面细化，不等于新增高清雕刻或恢复原版缺失贴图。

原生动画实例将待机与行走混合，在胸部以上叠加施法；死亡使用全身动画。行走速度由主动移动驱动，被击退滑行不会自动触发行走。最新版本加入真实施法前摇：天罚依据S001字段恢复0.7秒，其他技能抬手按UE手感预设配置，见第15章。效果在前摇结束时才释放；动画随施法阶段播放，支持取消。原始网格仍为低模，头脸、衣料褶皱与细节属于下一阶段重制内容。

## 实际画面设置

移除启动脚本固定 1600×900 的限制。首次独立游戏采用桌面分辨率、无边框、高画质预设与 60 FPS 上限；超过 2560 宽时场景内部渲染 67%，UI保持输出分辨率。高画质档采用TAAU时域重建，精细档保留TSR；不声称原生4K场景渲染。显式传入 Width/Height 时优先遵循启动参数。编辑器PIE不强制改用户桌面设置。

Windows游戏启用 `bAllowHighDPIInGameMode=True`，避免高缩放屏幕被当作较小的逻辑桌面，再由Windows放大。显示设置迁移版本为3；已有样机配置在下一次无显式分辨率启动时更新一次，随后继续保存用户选择。仅提高截图尺寸不等于修复高DPI输出，实际PNG尺寸和游戏保存的输出/场景渲染比例均需检查。

F6 切换 1080p、1440p 和桌面分辨率；F7 切换流畅、高画质、精细。4K输出对应场景50% / 67% / 83%，较低输出对应80% / 100% / 100%；这是可试玩的预算预设，不是已通过的帧率保证。两名本地玩家共享渲染设置。滚轮调整战斗镜头距离。

`Scripts/refine_arena.py` 通过UE材质和场景API生成版本化细化：不规则石块接缝、表面凹凸和粗糙度变化、流动熔岩与冷却浮壳、自建不规则岩石、暖色主光、克制的泛光；不改动逻辑安全区和技能数值。保留Lumen与虚拟阴影，时域重建按画质档位选择。HUD字体按实际输出像素栅格化，4K布局继续按视口缩放。

`Scripts/import_refined_assets.py` 新增256段圆周与多层侧缘的平台、带收腰/分层基座的柱体、更密的风化岩石，替换基本圆柱和尖锥外观。平台最大半径与柱体逻辑位置/半径不变。`Scripts/refine_stone_detail.py` 用已有材质节点替换重复波纹，增加斑驳矿物表面；不删除已被构造期资产引用而root的材质表达式。熔岩以暗色冷却壳为主，亮色集中在扭曲裂隙。

HUD采用统一暗色金属饰边、圆形技能纹章、独立冷却环、分段生命条、清楚分开的生命/击退/金币信息与回合徽记；商店加强选中态、详情分区和确认按钮，沿用原操作与独立玩家焦点。新增F6/F7提示，界面仍按真实视口像素绘制。

## 验证与限制

已通过完整Editor编译、20项PIE核心回归、9项角色骨骼/外观检查及3项规则自动化。角色检查脚本为 `Scripts/verify_character.py`，实际报告在 `Saved/Validation/character.json`。Windows烘焙、最终截图和分屏表现以第12章本轮记录为准。

最终正式品质仍需要更高细节的自有术士模型与贴图、完整特效和声音，以及持续实战和分屏性能验收。原地图地格、安全面刷和全部障碍预设尚未完成，不以更好看的场景替代规则还原。

独立包检查曾发现UE5.9的 FAnimNode_Root 在原生图中没有蓝图编译的 NodeData，PIE可运行而烘焙后在追踪节点名称时断言。已改为使用最终原生混合节点作为根，保留同一动画混合流程；失败证据保存在 `Saved/Validation/character-cooked-root-assert.log`。独立包启动检查用于防止仅凭PIE误判完成。

实际截图还发现Python颜色和旋转结构的位置参数与预期顺序不同：Color为BGRA、Rotator反射参数并非设计稿的pitch/yaw/roll顺序，导致熔岩补光偏蓝和部分岩石倾倒。已用具名字段重建颜色与朝向；主光改为中性正面侧光，补光从18000降至35，避免三套衣服都被染成橙色；头饰金属与玄武岩材质补充Nanite用途，防止独立包回退默认材质。

主光继续投射阴影，四盏弱岩浆补光不重复生成点光阴影。石材凹凸法线依据网格法线定向，并沿网格法线偏移，修复竖直柱体/平台侧缘因按世界Z翻转而产生的碎斑。

真实桌面输出使用普通Windows启动验证：离屏模式使用FNullApplication虚拟桌面，unattended默认也会抑制每显示器DPI，二者不能证明真实桌面自适应。已实际观察到3840×2160输出、67%场景重建和per-monitor DPI日志。`Scripts/CaptureVisuals.ps1` 使用游戏运行5秒后的截图；其余离屏截图只用于模型、商店和分屏布局检查，测试结束恢复测试前的显示配置。

本机同一静态场景的4K/67%短样本比较中，TSR帧时间中位数约22.85ms、GPU约22.36ms；TAAU帧时间约16.67ms（60帧上限）、GPU约9.04ms。因此默认高画质采用TAAU，精细档保留TSR；没有关闭Lumen/主光阴影换取这项结果。原始对比在 `visual-native-taau.log` 和对应CSV，最终默认设置复测见 `visual-report.json`。这里只是短时静态采样，尚未完成移动细弹道拖影、多人技能叠加与持续分屏60FPS验收。

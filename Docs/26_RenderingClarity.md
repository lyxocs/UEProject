# 轮廓、材质清晰度与抗锯齿

2026-11-27。用户反馈模型、材质边缘不清晰。此次检查发现本机玩家配置仍是50%场景比例、旧版低档TAA；4K输出实际只渲染约1920×1080。放大、程序化细纹的欠采样和模型本身的折面需要分别处理。

## 实现

- ESC → 画面与性能新增「抗锯齿 / 重建」：高质量TAA、均衡TSR、精细TSR。与光照、阴影和反射独立，改变AA不改场景比例或帧率上限，选择保存到本机配置。
- 低配／流畅用高质量TAA（UE AA质量3，TemporalAA.Quality=2）；均衡／高画质用TSR、100%历史尺寸；精细用TSR、200%历史尺寸。后者开销更高。不能把TSR精细档当作低端机默认。
- 低配／流畅／均衡／高画质／精细基础比例为67／85／100／100／100%。场景宽度预算为1600／1920／2560／3840／3840，最低50%；例如4K均衡约67%，1080p均衡100%。玩家可以手动提高比例；老玩家自选配置不会被启动时强制覆盖。
- 衣料、金属划痕、皮肤细纹使用UV像素导数过滤；远处停止显示小于像素的细纹，近处保留原有幅度。地面石缝的基础颜色使用屏幕导数平滑，不对已含导数的法线节点嵌套求导。保留配色、受击材质输入、骨骼、动画、碰撞和玩法数值。
- 菜单新增行后仍适配左右分屏。Canvas图标沿用原有绘制；世界AA并不覆盖Canvas。

脚本 `polish_material_clarity.py` 只通过UE修改四个项目自有材质，重复运行零修改；资产变化必须完整Cook。`CaptureClarity.ps1` 固定1920×1080、同档光照，可比较TAA/TSR和50～100%比例，静态角色近景不冒充实际战斗性能。`ProfileClient.ps1 -Preset Fast -Participants 8 -Label clarity` 单独测试动态八人左右分屏，不覆盖旧版证据。

## 画面边界

当前角色仍由原地图模型细化而来。肩部、兜帽、法杖和场景立柱的轮廓折面不是显示锯齿，提升AA或锐化不能生成缺少的造型、布料层次或贴图。此次没有制作新的高精角色；后续美术工作需要重做这些资产并保留现有骨骼/动画接口。不要用过度锐化掩盖低分辨率，容易增加闪边。

Editor与Game完整编译、660个包完整Cook及Windows打包成功。52项PIE画面设置检查、9项角色骨骼/行走/施法/外观回归、46项实际打包客户端检查通过，合计107项。后者通过多次独立进程确认TAA实际方法2/质量2、TSR方法4和100/200历史尺寸，以及旧配置、八人设置、22项改键跨启动保存；没有把设置字段变化当作渲染器已经生效的唯一证据。四个材质的脚本第二次运行零改动。原地图SHA256未改变。

最终程序1920×1080/100%TSR的角色近景和竞技场截图已生成并查看；衣料轮廓和地面接缝比旧版50%更清楚，模型折面仍存在，不能称为高精角色。实际打包进程无材质编译失败或默认材质回退。

1600×900八席左右分屏、流畅85%/高质量TAA，1200帧去除前300帧后，中位12.699ms（约78.7FPS）、P95为15.351ms，GPU中位10.808ms，来源 `Profile(20261127_104325).csv`。旧版75%曾测82.1FPS；两次AI过程和背景负载不同，不把差值当作严格性能回归百分比。后续均衡档采样未在58秒内完成，不计为通过或稳定帧率证据。

采样期间发现客户端和编辑器均关闭后GPU仍有约60～70%占用、约5GiB显存使用，另一个游戏和多个GPU程序仍在运行；未关闭用户其他程序。TSR静态图约14～16FPS受此环境影响，不能与先前空闲时的短测直接比较，更不能据此保证实际流畅度。仍需无其他游戏负载时重新测量TSR。实体双手柄和干净PC未在本轮实测。
